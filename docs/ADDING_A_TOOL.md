# Как добавить инструмент в NIMVORO

Лаунчер ничего не знает об утилитах заранее. Всё, что он показывает и устанавливает, берётся из трёх мест:

1. `catalog.json` в этом репозитории — список репозиториев утилит.
2. `nimvoro.json` в корне репозитория утилиты — описание, иконка, скриншоты, имя exe.
3. Последний GitHub Release утилиты — версия (`tag_name`) и zip для установки.

Чтобы добавить новый инструмент, не нужно пересобирать лаунчер: достаточно выполнить шаги ниже и дописать строку в `catalog.json`.

## 1. Манифест `nimvoro.json`

Кладётся в корень репозитория утилиты, ветка `main`.

```json
{
  "schema": 1,
  "id": "random-wheel",
  "name": "Random Wheel",
  "tagline": "Колесо фортуны для розыгрышей",
  "description": "Абзац-два о том, что это и зачем.",
  "features": [
    { "title": "Колесо и список", "text": "Два режима выбора победителя." }
  ],
  "category": "Утилиты",
  "accent": ["#4f6bff", "#8a5bff"],
  "icon": "assets/icon.png",
  "screenshots": ["assets/screenshots/1.png", "assets/screenshots/2.png"],
  "exe": "RandomWheel.exe",
  "asset": "RandomWheel-win-x64.zip",
  "requirements": ["Windows 10/11 x64"],
  "settingsDir": "%APPDATA%\\Random Wheel"
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `schema` | да | Версия формата, сейчас `1` |
| `id` | да | Уникальный id, совпадает с `id` в `catalog.json`; им же утилита зовёт `NIMVORO.exe --update <id>` |
| `name`, `tagline` | да | Заголовок карточки и подзаголовок |
| `description`, `features` | да | Текст в попапе |
| `accent` | нет | Два цвета градиента для логотипа и акцентов карточки |
| `icon` | да | PNG 256×256, путь внутри репозитория |
| `screenshots` | нет | PNG/JPG для карусели, путь внутри репозитория |
| `exe` | да | Путь к exe внутри распакованного zip |
| `asset` | да | Имя zip в релизе. Без версии в имени, чтобы работала ссылка `releases/latest/download/<asset>` |
| `requirements` | нет | Строки, показываются в попапе |
| `settingsDir` | нет | Где утилита хранит настройки (для кнопки «Папка настроек») |

## 2. Релиз

- Тег `vX.Y.Z` (semver). Версия в тег-е должна совпадать с версией, вшитой в exe.
- В релизе лежит zip с именем из `asset`. Внутри zip — готовая к запуску папка: exe и всё, что ему нужно, в корне архива.
- Шаблон workflow — `.github/workflows/release.yml` в любой из существующих утилит: собирает на `windows-latest`, пакует zip и публикует релиз на push тега.

## 3. Проверка обновлений внутри утилиты

У каждой утилиты в настройках есть переключатель «Проверять обновления при запуске» (по умолчанию включён).

1. При запуске, если переключатель включён: `GET https://api.github.com/repos/<owner>/<repo>/releases/latest`, сравнить `tag_name` с собственной версией.
2. Если есть новее — показать плашку «Доступна версия X» с кнопкой «Обновить».
3. Кнопка «Обновить»: прочитать `%APPDATA%\NIMVORO\launcher.json` (`{"path": "C:\\...\\NIMVORO.exe"}`, лаунчер пишет его при каждом запуске).
   Если лаунчер есть — запустить `NIMVORO.exe --update <id>` и завершиться. Если нет — открыть страницу релиза в браузере.

Готовые реализации: `src/nimvoro.rs` в Rust-утилитах (копируется как есть), `src/updater.js` в Smart Switcher, `Updater.cs` в FPS Overlay.

Лаунчер на `--update <id>` скачивает новый zip, при необходимости закрывает старый процесс, заменяет файлы и запускает утилиту.

## 4. Строка в `catalog.json`

```json
{ "id": "random-wheel", "repo": "GrigoryyKach/random-wheel" }
```

Лаунчер загружает свежий `catalog.json` из `main` при каждом запуске; если сети нет — использует копию, вшитую в сборку.
